# Паспорт выгрузки обращений (аудит данных)

Запуск всех запросов из корня репозитория: `python3 src/sqlmd.py reports/data_audit.md`.

## Сырые данные и чистка

### 1. Сколько строк в `tickets`, сколько в ней разных номеров обращений и сколько строк в S
**Ответ:** В 'tickets' 7033 строки, разных номеров 6760, в 'clean' 6760. Пропали 273 строки (3,9%) - это точные дубли: строки, совпавшие во всех полях. Коллега оставил по одной копии ('SELECT DISTINCT *'), число уникальных строк тоже 6760.
```sql
SELECT
    (SELECT COUNT(*) FROM tickets),
    (SELECT COUNT(DISTINCT id) FROM tickets),
    (SELECT COUNT(*) FROM clean),
    (SELECT COUNT(*) FROM (SELECT DISTINCT * FROM tickets));
```

### 2. Каналы в `tickets` и в `clean`. Что коллега исправил?

**Ответ:** В сырых данных один канал записан двумя способами: 'чат' (2711) и 'Чат' с большой буквы (163). Коллега привел все к 'чат': стало 2770. Это на 104 меньше, чем 2711 + 163 = 2874, потому что часть строк была дублями. Остальные каналы не тронуты.

```sql
SELECT channel, COUNT(*) FROM tickets GROUP BY channel ORDER BY 1;
SELECT channel, COUNT(*) FROM clean GROUP BY channel ORDER BY 1;
```

### 3. Темы в `tickets` и в `clean`. Как в сырых данных записана пустая тема? Что сделал коллега? Всё ли он исправил?

**Ответ:** Пустая тема в сырых данных записана двумя способами: пустая строка ' '' '  (287) и текст 'NULL' (157). Коллега заменил только пустую строку на 'без темы' (278 после удаления дублей), а текст 'NULL' (152) оставил - это его ошибка. Реально "тема неизвестна" у 430 обращений (278 +152), это 6,4% выгрузки.

```sql
SELECT topic, COUNT(*) FROM tickets WHERE topic IN ('', 'NULL') GROUP BY topic;
SELECT topic, COUNT(*) FROM clean WHERE topic IN ('без темы', 'NULL') GROUP BY topic;
SELECT COUNT(*) FROM clean WHERE topic IN ('без темы', 'NULL');
```

### 4. Даты: сколько строк в формате `ДД.ММ.ГГГГ` и в другом? Сколько обращений «после 1 апреля», если сравнить даты в `tickets` как есть, и сколько по `period` в `clean`? Какой период охватывает выгрузка?

**Ответ:** В формате ДД.ММ.ГГГГ 2119 строк, в другом 4914. "После 1 апреля" при сравнении как есть - 3337, по period в clean - 3549. Расходятся, т.к. даты вида 17.06.2025 начинаются с цифры 1, а 2025-04-01 - с цифры 2, и текстовое сравнение считает все даты с точками "раньше". Выгрузка охватывает период с 1 января по 30 июня 2025.

```sql
SELECT COUNT(*) FROM tickets WHERE created_at LIKE '__.__.____%';
SELECT COUNT(*) FROM tickets WHERE created_at NOT LIKE '__.__.____%';
SELECT COUNT(*) FROM tickets WHERE NOT (created_at < '2025-04-01');
SELECT COUNT(*) FROM clean WHERE period = 'после';
SELECT MIN(created), MAX(created) FROM clean;
```

## Пустые значения

### 5. Сколько обращений бот закрыл сам и у скольких из них нет сотрудника? Что значит пустой сотрудник? Что стало с остальными?

**Ответ:** Бот закрыл 1667 обращений, у 1570 из них нет сотрудника. Пустой сотрудник значит, что человек не работал: обращение закрыл бот. У остальных 97 закрытых ботом сотрудник есть: клиент переоткрыл обращение, и оно ушло к человеку.

```sql
SELECT COUNT(*) FROM clean WHERE bot_result = 'закрыл';
SELECT COUNT(*) FROM clean WHERE bot_result = 'закрыл'AND agent_id IS NULL;
SELECT COUNT(*) FROM clean WHERE bot_result = 'закрыл' AND agent_id IS NOT NULL;
```

## Нумерация

### 6. Сколько номеров обращений пропущено? Сколько до 1 апреля и сколько после? Что это может значить для выводов?

**Ответ:** Номера идут сплошной нумерацией, но часть пропущена: до 1 апреля 32 номера, после 1 апреля 155 (всего 187). После апреля пропусков в несколько раз больше. Мы не знаем, что в них: если пропали успехи бота, он лучше, чем видно: если провалы, хуже. Поэтому вывод про бота нельзя считать точным.

```sql
SELECT period, COUNT(*), MAX(num) - MIN(num) + 1 - COUNT(*) FROM clean GROUP BY period;
```

## Бот

### 7. После 1 апреля: в каких каналах работает бот? Сколько он закрыл сам и сколько передал человеку?

**Ответ:** После 1 апреля бот работает в письменных каналах: чат, почта, форма. В телефоне бота нет (bot_result = 'нет'). В письменных каналах бот закрыл сам 1667 обращений, передал человеку 1021.

```sql
SELECT channel, bot_result, COUNT(*) FROM clean WHERE period = 'после' GROUP BY channel, bot_result ORDER BY channel;
SELECT bot_result, COUNT(*) FROM clean WHERE period = 'после' AND written = 1 GROUP BY bot_result;
```

### 8. Время первого ответа до и после апреля — отдельно для письменных каналов и для телефона. Кто отвечает первым после апреля?

**Ответ:** В письменных каналах медиана первого ответа была 50,1 минуты, стала 0,4 минуты. По телефону почти не изменилась: 3,1 и 3,0 минуты. После апреля первым отвечает бот (0,4 минуты у закрытых и переданных). first_reply_at показывает ответ от кого угодно, поэтому по нему нельзя судить о работе людей.

```sql
SELECT period, written, MEDIAN(first_reply_min) FROM clean GROUP BY period, written;
SELECT bot_result, MEDIAN(first_reply_min) FROM clean WHERE period = 'после' GROUP BY bot_result;
```

## Возвраты

### 9. Сколько обращений переоткрыто и после скольких был возврат? Чем одно отличается от другого? Как это выглядит до и после апреля?

**Ответ:** Переоткрыто 579 обращений, возврат был после 531. Переоткрытие: клиент вернулся в то же обращение. Возврат: тот же клиент создал новое обращение с той же темой в течение 7 дней. До апреля: переоткрытий 273 и возвратов 200 из 3211 обращений. После апреля: переоткрытий 306(почти столько же), а возвратов 331 из 3549 (стало заметно больше). Флаг переоткрытия не видит клиентов, которые написали заново.

```sql
SELECT SUM(reopened), SUM(came_back) FROM clean;
SELECT period, COUNT(*), SUM(reopened), SUM(came_back) FROM clean GROUP BY period;
```

## Справочник

### 10. Сколько обращений вёл каждый сотрудник и сколько — без сотрудника? Есть ли в справочнике сотрудник без обращений? Как записан номер сотрудника в `clean` и в `agents`?

**Ответ:** В clean 18 разных сотрудников (коды a01...a18), без сотрудника 1570 обращений. В справочнике 19 разных людей, значит один человек обращений не вёл: это последний по номеру, igor_h. Номера записаны по-разному: в clean a01, в справочнике 1, поэтому напрямую по номеру они не соединяются.

```sql
SELECT agent_id, COUNT (*) FROM clean GROUP BY agent_id ORDER BY 1;
SELECT COUNT(DISTINCT agent_id) FROM clean;
SELECT COUNT(DISTINCT login) FROM agents;
SELECT id, login, hired_at FROM agents ORDER BY CAST(id AS INTEGER) DESC LIMIT 1;
SELECT id FROM agents LIMIT 1;
```

## Промежуточный вывод

_Три утверждения, которые нельзя сделать по этой выгрузке сразу, хотя хочется. У каждого — число, которое это показывает._

1. **«Бот закрыл 1667 обращений, значит он решил 1667 проблем».** Нельзя: «закрыл» — это отметка бота, а не результат для клиента. Доля возвратов (тот же клиент, та же тема в течение 7 дней) выросла с 6,2% (200 из 3211) до 9,3% (331 из 3549).
2. **«Время первого ответа в письменных каналах упало с 50,1 до 0,4 минуты, значит клиентам стало лучше».** Нельзя: после апреля первым отвечает бот, а в нумерации пропущено 187 номеров, из них 155 после апреля (до апреля 32). Мы не знаем, что в этих обращениях: если там успехи бота, он лучше, чем видно; если провалы — хуже.
3. **«Обращений без темы 278 (4,1%)».** Нельзя: коллега заменил только пустую строку, а текст `NULL` оставил. Реально тема неизвестна у 430 обращений (6,4% выгрузки). Похожая ловушка в датах: сравнение «как есть» даёт 3337 обращений после 1 апреля, а по разобранным датам — 3549.
